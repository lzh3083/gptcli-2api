转售与分发指南

Codex 自动化注册成果对接 CLIProxyAPI (CPA) / Sub2API / OneAPI / NewAPI 实战流程

分发模式 1：对接 CLIProxyAPI (CPA) —— 推荐首选

CPA 天然支持 Codex PKCE 凭证与 OAuth 自动刷新，聚合为标准 OpenAI 接口供下游转售。

方案 A（本地/内网目录挂载 · 秒级热加载）：

流水线成功注册的账号凭据会自动保存在本机的 /app/data/cpa_auth_files/codex-<email>-free.json。若 CPA 部署在同一服务器或同内网，只需将该目录挂载至 CPA 容器的 /cliproxyapi/auths 目录，CPA 就会自动扫描并秒级加载所有新号。

方案 B（远程 API 自动推送）：

进入「系统与分发设置」->「CLIProxyAPI」，填入远程 CPA 的 Base URL 与 Management Key，并勾选自动推送。新注册的 Codex 账号将在诞生后秒级直传至目标 CPA。

分发模式 2：对接 Sub2API

自动按分组将 Codex 凭据录入 Sub2API，实现商业化限流与并发控制。

1. 在「系统与分发设置」->「sub2api 对接」中填入 Sub2API 地址、管理员邮箱与密码；

2. 点击「拉取分组列表」选择或创建目标分组（例如 Codex-Pool）；

3. 开启「自动推送」或在「账号管理」中勾选账号点击「推送到 Sub2API」，账号即刻完成导入与配额生效。

分发模式 3：对接 OneAPI / NewAPI 转售计费

标准商业化中转计费平台接入推荐架构。

推荐架构链路：gptcli-2api (生产) ➔ CLIProxyAPI (聚合与按需刷新) ➔ OneAPI / NewAPI (用户计费与售卖)

1. 为什么必须经过 CPA 聚合？ OneAPI 仅支持标准的静态 API Key 轮询，不支持原生的 PKCE OAuth refresh_token 换票。CPA 会自动接管账号生命周期并伪装为标准 OpenAI 服务；

2. OneAPI 渠道配置：类型选择 OpenAI，代理地址填入 CPA 的对外服务地址（如 http://<CPA_IP>:8000），密钥填入 CPA 分配的通用转发 Key；

3. 直接导出密钥：若需要单 Token 导入其他平台，可在「账号管理」中点击「导出 OneAPI 渠道」一键导出全量密钥文本。
